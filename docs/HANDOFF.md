# 인수인계: 통역 드릴 v5.3 (2026-10-27)

다음 세션은 이 파일부터 읽고 시작한다. 이 저장소는 공개이므로 개인 기록·작문·연락처는 적지 않는다.

## 0. v5.3: 기본 문항을 내림 (2026-10-27, 가장 먼저 읽을 것)

- 사용자가 풀다가 맞는 답이 감점되는 문항을 발견했다: 「異常が発生したら、直ちにご連絡ください」(直ちに 감점), 「装備を点検して」(装備 무시). 같은 종류의 지적이 두 번째였다.
- 원인: 기본 57문항과 롤플레이 문서는 Claude가 직접 쓴 일본어를 모범 답으로 두었고, 외부 근거로 검증하지 않았다.
- **새 원칙(검증 관문)**: 문항은 Claude가 만들어도 되지만, 내기 전에 학습자가 낼 만한 다른 답(한자어 직역, 동의어, 말투만 다른 표현)을 나열하고 하나하나 정답·가능(말투·장면 차이)·부자연·오류로 판정해 이유와 근거(사전, 사용분류 사전, 문형책, 코퍼스)를 적는다. **근거로 설명하지 못하는 오답은 오답으로 두지 않는다.** 판정표에 없는 답은 「질문하기」로, 비교 뒤 모범 답 따라 말하기. 근거 없는 설명은 「Claude 설명 (근거 없음)」 표시.
- v5.3 변경: `SETS`·`ITEMS`·`RP`·`SET_CHK`·`CHK`를 비움. 문항이 없으면 연습·핸즈프리 탭에 이유를 알리는 안내, 롤플레이 탭은 안내만. 기능(기기 점검, 문제 추가하기, 녹음, 핸즈프리, 복습 간격)과 기록은 그대로. 이전 문항은 v5.2(e3b70a3) 기록에 있다.
- 다음: 관문을 통과한 문항(직접 만든 것은 이 저장소에 둘 수 있음)과 교재(비공개) 기반 「교재 팩」(기기에서 불러옴, 교재 자료는 이 저장소에 넣지 않음)으로 다시 채운다. 전체 계획은 드라이브의 LA-11 v6(앱 전면 검토와 수정 기획).
- 테스트: v5.2 항목(사용자 지정 세트로) + 빈 상태(문항 0개에서 모든 탭 열림, 콘솔 오류 없음) → 46항목 통과.

## 1. 지금 상태 (2026-10-27 갱신)

- 통역 드릴 v5.0·**v5.1은 main에 합쳤다**(2026-10-27, GitHub Pages 반영 확인).
- 아이폰 기기 점검 v5.0(iOS 18.7, Safari): 음성 읽기·마이크·스피커 새어 들어감·음성 인식·핸즈프리 ✓, **녹음 다시 듣기 ✗(안 들림)**, 음성 인식이 같은 말을 두 번 적음.
- 아이폰 기기 점검 v5.1: **⑥ 녹음 ✓(audio/mp4)로 해결.** 그러나 ⑤ 인식이 여전히 「会計お願いします会計お願いします」, **⑦ 핸즈프리 버튼이 먹통**(결과 「안 함」).
- 이를 고친 **v5.2를 브랜치 `drill-v5.2`에 올렸다. main 합치기는 사용자가 정함.**
  - ⑦ 먹통 원인(추정): v5.1의 ⑥이 녹음 자동 재생을 `await el.play()`로 기다렸고, 아이폰에서 이 약속이 끝나지 않으면 `CK.busy`가 풀리지 않아 다른 테스트 버튼이 잠겼다. → 기다리지 않음. 답(들림/안 들림)을 고르면 그 테스트를 끝난 것으로 보고 잠금을 푼다.
  - ⑦: 화면 켜짐 유지 요청은 1.5초만 기다림, 단계 표시(① 한국어 → ② 쉬는 중 → ③ 일본어), 결과에 각 읽기가 끝난 방식(끝까지/시간 초과/오류)과 화면 켜짐 유지 상태를 적음. `speak()`가 끝난 이유("end"·"error"·"timeout")를 돌려줌.
  - ⑤: 비교할 때 띄어쓰기·문장부호를 무시, 이미 모은 글 끝과 같으면 건너뜀, 앞 조각을 이어 키운 결과는 바꿔 끼움, 한 조각 안에 같은 말이 두 번이면 하나로. **점검 결과에 기기가 보낸 원본(`ASR.log`, F=확정·i=중간)을 함께 적는다** → 다음 아이폰 점검 결과로 실제 형태를 확인할 것.
  - 테스트: v5.1 항목 + 재생 약속이 끝나지 않는 상황에서 ⑦ 진행, 인식 되풀이 3가지(문장부호 차이·한 조각 안 반복·이어 키우기) → 37항목 통과.
- v5.1에서 고친 것:
  - 녹음·모범 답을 재생할 때 마이크를 잠시 닫고(`micPause`), 다음 문장에서 측정·녹음을 시작할 때 다시 연다(`capStartMic`). 기기 점검 ⑥은 녹음을 멈춘 직후 마이크를 닫고 재생.
  - 녹음 형식 `audio/mp4`(AAC) 우선, 실제 형식을 `REC.type`에 저장해 점검 결과에 표시. `<audio playsinline>`.
  - 점검 ⑥ 첫 「안 들림」 → 무음 스위치·음량 확인 안내 후 다시 묻고, 그래도 안 되면 녹음 옵션 끄기 안내.
  - 음성 인식: 확정 결과를 매번 처음부터 모으고 바로 앞과 같으면 건너뜀. 다시 시작 전까지의 글은 `_base`에 두고, 다시 시작한 뒤 첫 결과가 `_base` 끝과 같으면 건너뜀.
  - 지워진 녹음(새 세션·핸즈프리 시작 때 지움)은 재생기 대신 안내 문구로 표시 (전에는 결과 화면에서 파일 없음 오류).
  - 테스트: Playwright(가짜 마이크·음성 읽기·중복을 보내는 가짜 음성 인식, v5.0에서는 같은 가짜로 중복이 재현됨)로 연습 탭(듣고 통역 → 답 보기 → 녹음 재생 → 다음 문장 재시작), 핸즈프리, 기기 점검 7항목, 콘솔 오류, 375px 폭 확인.
- **다음 확인 (아이폰)**: v5.2를 main에 합친 뒤 ① 기기 점검 ⑤ 결과의 「원본」 확인(중복이 남으면 원본 형태에 맞춰 다시 고침) ② ⑦ 핸즈프리를 **화면을 끈 상태로** 확인.
- 남은 의문: 핸즈프리는 말하는 동안 마이크를 연 채로 모범 답을 읽는다. 아이폰에서 이때 소리가 작아지면 핸즈프리에도 같은 처리가 필요하다(⑦은 마이크 없이 점검하므로 실사용에서 확인).

## 3. 지금까지의 판단 (다시 논의하지 않아도 되는 것)

- **자동 채점의 한계**: 음성 인식은 틀린 말을 맞게 다듬어 적는다 → 오류 찾기에 쓰지 않고, 남는 것(목표 표현·피할 표현·결론 위치)만 본다. 정확성은 녹음 + 포인트 자기 체크 + 주 1회 Claude 채점으로.
- **피드백 순서**: 1차 AI(자동 확인·Claude 채점) → 2차 사용자 확인(녹음 재청취) → 라운드 뒤 문제점 재검토.
- **P-01 한국어가 공문체인 것은 의도** (그 문체를 말로 푸는 것이 훈련 목표). 일상 구어는 H1·C1에서.
- **저작권**: 드라마·애니 대본을 앱에 넣지 않는다. 장면 구조와 유행어 경향만 참고해 대사는 새로 쓴다. 공식 시나리오북은 구입해 개인 참고용으로. 무단 대본·자막 사이트는 쓰지 않는다. 애니 대사는 역할어(〜だぜ 등)를 걸러야 한다.
- 이 앱은 개인 학습용 (사업 목적 아님).

## 4. 남은 과제 (우선순위)

1. v5.1 main 합치기 → 아이폰 기기 점검 ⑥·⑦ 재확인 → 1라운드 테스트 (H1·C1, 🎧 켜고) → 결과지·점검 결과로 문제점 재검토
2. **콘텐츠 양** (가장 큰 약점): 세트당 30문장 이상. 소스는 `docs/sources.md`
   - AI Hub 「일상생활 및 구어체 한-일 번역 병렬 말뭉치」(546), 「방송 콘텐츠 한-일 번역 병렬 말뭉치」(71263): 용량이 커서 **로컬 PC에서** 받아 처리할 예정
   - 받은 뒤: 장면·레벨로 거르기 → 한국어 문어체는 구어로 다듬기 → 일본어 번역투 점검(名大会話コーパス·CEJC 검색으로 확인) → 의미 단위·함정 어휘(kw·ng) 붙여 JSON으로 → 「문제 추가하기」로 넣기 (또는 기본 문항으로 커밋)
3. 처음 사용 흐름: 처음 열면 기기 점검으로 안내하고, 결과에 맞춰 옵션을 자동으로 켜기
4. 재미: C1을 같은 캐릭터가 나오는 이어지는 에피소드로
5. 저장소 정리: 보류된 옛 파일(`la_0-*`, `la_1*`)을 `archive/`로
